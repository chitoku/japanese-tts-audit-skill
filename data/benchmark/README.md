# Japanese TTS Audit — 誤読観測・開発ベンチマーク

今後の正本はこのフォルダです。実験ごとの `research/` は出典・検証記録として残し、新しい実例はこの台帳に登録します。単に「間違いやすそうな語」を集めた問題集と、実際に誤読された固定音声を分けて管理します。

**現在版：[v0.1.0](versions/v0.1.0/manifest.json)**。CLI/Skillのバージョンとは独立しています。

- [観測済み・報告済みの語と読みを一覧で見る](WORDLIST.md)
- [語の台帳：terms.jsonl](versions/v0.1.0/terms.jsonl) — 1,150表記。観測ID・例文IDへのリンクを持ちます。捕物／捕り物の表記別名も保持します。
- [台本と読み：prompts.jsonl](versions/v0.1.0/prompts.jsonl) — 2,241件。従来の2,000文、歴史語彙200文、旧100文、対象語外で発見した例などを統合・重複排除。参照読みが異なる場合は別IDです。
- [実際の観測：observations.jsonl](versions/v0.1.0/observations.jsonl) — 125件。語・台本・期待読み・聴取読み・モデル表記・固定音声SHA-256・元の判定／メモ・出典を結び付けます。

**1,150表記すべてで誤読を確認したわけではありません。** 台本プールは収集候補を含み、自然さや参照読みをすべて再検証したものではありません。生成対象外65例を除く2,176例は選択可能な候補であり、確定した正解データという意味ではありません。

## 二つの用途

### 1. TTSの再現・比較用

`prompts.jsonl` の `text` と対象語の `expected_kana`／`accepted_readings` を使い、任意のTTSで新しく生成します。生成するたびに新しい観測を追加します。同じ語でもモデル・声・入力・生成回によって結果が変わるため、過去の誤読を新しいエンジンの正解ラベルとして流用しません。

`stage: candidate_prompt_not_gold` は仮説用例文です。`reviewed_observation_context` は聴取ラベル付きの実例に結び付いた文脈ですが、その文全体を保証しません。`generation_eligible: false` はユーザーが対象から外した別読み・文脈依存の語などです。許容読みを持つこと自体をすべて除外するのではなく、関心外の読み分け問題を優先対象から外します。表記・読みが違う重複候補や未検証の許容読みも含むため、採用版に昇格させる前に用例ごとの裁定が必要です。

### 2. Skill／CLIの検出性能を回帰テストするため

固定された生成音声と、特定の語の聴取ラベルで検出を評価します。

| 状態 | 観測箇所数 | 採点 |
|---|---:|---|
| `reviewed_error` 聴取済み誤読 | 32（23語） | 検出すべき箇所 |
| `reviewed_correct` 聴取済み誤警報対照 | 9 | 誤警報を出さない箇所 |
| `needs_adjudication` 要裁定 | 15 | 対象外 |
| `reported_lead` YouTube等の収集報告 | 39 | 対象外 |
| `excluded_variant` 別読み・参照の問題等 | 30 | 対象外 |

誤読32箇所の内訳はElevenLabs 13、VOICEVOX 17、Google 2。繰り返し生成を含む箇所数です。**32件すべてが「だんこん・せんぞう系」ではありません。** `phenomenon` で音の変化・複合語の読み・脱落などを区別します。`phonetic_corruption` 等は観測上の分類であり、音訓一覧との網羅的照合やDeep Learning内部の原因を証明したものではありません。より厳密な辞書非整合カテゴリの裁定は今後の作業です。

これは単独聴取者の記録を基に固定した**開発・回帰テスト用の参照セット**です。独立した複数人の正解認定、未使用のホールドアウト、世の中全体の誤読率を示す標本ではありません。既存の開発に利用した音声を含みます。独自リーダーボードは作りません。

対照9箇所も含め、ラベルは対象の語に限定します。他の語や文全体を正読保証しません。音声は71ファイル、約18.8MBを同梱し、要裁定・除外例も再聴取できます。YouTube音声は同梱していません。

## 実行方法（有料API不要）

Repoのルートで：

```sh
python tools/benchmark.py validate
python tools/benchmark.py export --out outputs/benchmark-v0.1.0-run
```

`export` は採点する41箇所について音声・台本・参照読みと `jobs.jsonl` を出力します。聴取された誤った読みや正誤ラベルは実行用ジョブに含めません。各ジョブは既存のCLIへ渡せます。

```sh
tts-audit check PATH_TO_AUDIO --script PATH_TO_SCRIPT --readings PATH_TO_READINGS --out OUTPUT_DIRECTORY
```

この `check` は通常ローカルASRを実行するため、未導入の場合はモデルの準備が必要です。ベンチマーク管理ツール自体は認識・生成を呼びません。参照読みはテキスト照合で使用し、ASRへの正解誘導には使わないでください。

`report.json` の `findings` を、ジョブの `id` と `audio_sha256` に組み合わせてJSONLで保存します。

```json
{"id":"O-...","audio_sha256":"...","findings":[{"script_start":0,"script_end":2}]}
```

検出なしは `findings: []`。採点対象の全IDが必要です。省略したケースを分母から落とすことはできません。

```sh
python tools/benchmark.py score outputs/benchmark-predictions.jsonl
```

対象語の文字範囲に重なる警告を検出と数え、TP/FN/FP/TN、適合率、再現率、誤警報率を返します。ラベルのない周囲の警告は採点しません。文章全体への警告でも重なれば検出となるため、範囲の精密さや実際の確認作業量を測る指標は別途必要です。常に全文を警告すれば対照9箇所が誤警報になります。

## 登録・変更ルール

1. 語だけでなく、元の台本・語の位置・期待読みの根拠を登録します。対象語外の発見も独立した観測にします。
2. 新しい音声にはSHA-256、モデルと声、生成条件の記録を付けます。本文と対象語はUnicode文字単位の半開区間 `[start, end)` で結び付けます。音声内時刻が未確認なら未確認のまま保持します。
3. 聴取読み・元の判定ボタン・メモをそのまま保存します。ASR結果は観測補助で、正解ラベルの代わりにはしません。ボタンとメモが矛盾する「捕り物」「米」は要裁定のまま両方残しています。
4. YouTubeのコメント・字幕時刻は収集報告として登録し、音声付きの確定例とは分けます。元の台本、該当音声、文脈の確認後に採用します。生成サービスが不明なら不明のままです。「戦慄→せんぞう」も出典音声を回収できていないため報告枠です。
5. 採用・訂正・参照読みの変更は次版で行い、旧版を変更しません。新しい版の `manifest.json` に採点IDと全関連ファイルのハッシュを固定し、`current.json` を更新します。`terms.jsonl` も各版内に固定します。

音声ファイルは内容ハッシュで共有しますが、別版に使われているファイルを削除・置換しません。元データのバッチ時刻は `provenance.source_row` 内に残していますが、個別音声の時刻として使ってはいけません。現在の採点セットは正確な音素時刻の正解を持ちません。

初回移行は [import_benchmark.py](../../tools/import_benchmark.py) に記録しました。元のローカル実験出力が必要な一度限りの移行処理で、既存版への上書きを拒否します。普段の利用は `benchmark.py` だけで完結します。[元ファイルのハッシュ一覧](provenance/v0.1.0/source-files.json) と各観測内の出典行を保持しています。未整理の制作デモや生コメント全件まで移行済みという意味ではありません。

## 配布条件

コードのMITと、合成音声・辞書・第三者の出典資料の利用条件は別です。同梱音声は現在のPrivate Repo内の研究用資産です。音声／データセットの再配布ライセンスはまだ設定していません。一般公開前に各提供元・音声モデルの利用条件と権利表記を確認します。YouTube報告はリンクと必要な事実・読みだけを収集し、動画やコメント全文を再配布していません。
